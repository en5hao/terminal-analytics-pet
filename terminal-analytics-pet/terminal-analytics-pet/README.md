# Аналитика терминального оборудования (Pet-проект)

Сквозной кейс анализа данных сети банкоматов/платёжных терминалов:
очистка трёх разрозненных источников → SQL-анализ → интерактивный
дашборд Power BI → отчёт с выводами и рекомендациями.

Проект имитирует рабочую задачу аналитика данных в сервисном
подразделении ИТ-компании: найти расхождения между системами,
посчитать ключевые показатели и объяснить заказчику каждую цифру.

---

## 1. Контекст

Заказчик обслуживает сеть терминального оборудования (банкоматы,
платёжные терминалы). Данные лежат в трёх несвязанных системах:

- **Процессинг** — журнал транзакций;
- **Мониторинг устройств** — статус, остаток наличных, последнее подключение;
- **Система заявок** — инциденты и выезды инженеров.

Проблема: системы не синхронизированы, часть устройств «висит» как
онлайн, но фактически не обслуживает клиентов; нет единой картины
качества работы; заказчик требует объяснить каждое расхождение.

**Задача:** собрать данные, очистить, свести, найти расхождения,
посчитать KPI, построить дашборд и подготовить отчёт.

**Период:** 01.09.2026 — 30.09.2026. «Момент выгрузки» всех систем — 30.09.2026 23:59:59:
все проверки «старше 3 дней» считаются относительно него, а не относительно текущей даты.
**Объём:** 40 устройств, 696 сырых транзакций (655 после очистки), 30 заявок.
**Данные синтетические** (`scripts/generate_data.py`, фиксированный seed), структура и «грязь» приближены к реальным.

## 3. Ключевые шаги

### 3.1. Очистка и объединение (Power Query)
- Приведение форматов времени, удаление дубликатов, обработка
  пропусков в `amount`, исправление опечаток в `txn_type`.
- Транзакции сворачиваются до одной строки на устройство и левым соединением
  присоединяются к `device_status` — так находятся устройства со статусом `online`,
  но без связи или без транзакций более 3 дней.
- Результат — таблица `device_consistency` с колонкой `anomaly_reason`.
- Журнал очистки: 696 → 655 транзакций (−6 дублей, −14 без времени, −14 без суммы, −7 с отрицательной суммой).

### 3.2. SQL-анализ (PostgreSQL)
12 запросов: коэффициент успешности по устройствам, устройства-«лжецы»,
MTTR по моделям, топ кодов ошибок, временные аномалии в заявках,
заявки на несуществующие устройства, устройства с низким остатком
наличных, динамика по дням и др. Каждый запрос — с комментарием
о бизнес-ценности. Проверено на PostgreSQL 16.

### 3.3. Дашборд Power BI
- **Overview**: срезы (период, модель, локация), 4 KPI-карточки,
  линейный тренд, топ-5 проблемных устройств, таблица аномалий.
- **Device Detail**: страница drill-through — правый клик по устройству
  на Overview → детализация по транзакциям и заявкам этого устройства.

### 3.4. Excel
Транзакции с ВПР (модель, адрес, стоимость обслуживания), столбец `is_success`,
сводка по моделям/локациям на формулах, СУММЕСЛИ для итогов по моделям.

### 3.5. Отчёт (PDF)
Контекст → данные → очистка → KPI → расхождения → выводы и
рекомендации → приложение.

## 4. Ключевые выводы

KPI: Success Rate **88.7%**, MTTR **5.62 ч**, аномальных устройств **6**, транзакций **655**.

- **Model-X** даёт долю ошибок (failed + timeout) 16.4% против 6.1% у остальных моделей —
  рекомендуется проверить прошивку партии.
- **Model-Z**: timeout 7.8% при failed 2.8% — проверить каналы связи, а не «железо».
- **3 устройства** (ATM-007, ATM-014, ATM-022) числятся онлайн,
  но без связи 4,6–6,5 суток и без транзакций — проверить сетевой мониторинг.
- **3 новых устройства** (ATM-038, ATM-039, ATM-040) есть в мониторинге, но без транзакций.
- **MTTR**: hardware 6.0 ч, network 5.8 ч, software 3.9 ч —
  оптимизировать выезд по аппаратным и сетевым инцидентам.
- **Заявки M0012, M0018**: `resolve_time` раньше `dispatch_time` —
  проверить метки времени в системе заявок; **M0005, M0023** — на несуществующие устройства.
- **Устройства ATM-003, ATM-019, ATM-031** — остаток наличных < 20%,
  требуется внеплановая инкассация.

## 6. Как воспроизвести

1. Клонировать репозиторий, `pip install -r requirements.txt`.
2. Сгенерировать данные: `python scripts/generate_data.py` (или взять
   готовые CSV из `data/raw/`).
3. Открыть Excel/Power BI, загрузить `data/raw/*.csv`, повторить шаги
   из `power_query/queries.txt`. Сверка: `python scripts/clean_data.py` → `data/clean/`.
4. БД: `createdb terminal_analytics && psql -d terminal_analytics -f sql/schema.sql && psql -d terminal_analytics -f sql/load.sql`,
   затем `sql/queries.sql`.
5. Собрать `powerbi/terminal_dashboard.pbix` по `powerbi/BUILD_GUIDE.md`.
6. Открыть `excel/terminal_analysis.xlsx` (пересборка: `python scripts/build_excel.py`).
7. Прочитать `report/terminal_analysis_report.pdf` (пересборка: `python scripts/build_report.py`).
